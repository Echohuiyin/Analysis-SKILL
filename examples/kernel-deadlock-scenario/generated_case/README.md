# Cache Deadlock Reproducer

## Purpose

Reproduce ABBA mutex deadlock in cache subsystem, based on vmcore analysis showing:
- Task1: holds mutex_cache_read, waits for mutex_cache_write
- Task2: holds mutex_cache_write, waits for mutex_cache_read

## Build

```bash
make
```

Requires kernel headers and build environment.

## Run

```bash
# Load module
sudo insmod reproducer.ko

# Check kernel logs (deadlock should occur within 120 seconds)
dmesg | tail -f

# Expected messages:
# [  XX.XXX] cache_flush_thread: acquired mutex_cache_read
# [  XX.XXX] cache_read_thread: acquired mutex_cache_write
# [ 120.XXX] hung task: cache_flush blocked for >120s
# [ 120.XXX] hung task: cache_read blocked for >120s
```

## Expected Behavior

1. Module loads successfully
2. Two threads start with opposite mutex acquisition order
3. Deadlock occurs within seconds
4. Kernel hung task detection triggers after 120s
5. System may become unresponsive (expected)

## Kernel Configs Required

```
CONFIG_LOCKDEP=y
CONFIG_DEBUG_MUTEXES=y
CONFIG_DEBUG_LOCK_ALLOC=y
```

These configs enable:
- Lock dependency validation
- Mutex debugging
- Lock allocation tracking

## Debug Tips

- Check `/proc/lockdep` for lock dependency chains
- Check `/proc/lockdep_chains` for circular dependencies
- Use `crash` tool to analyze blocked threads if vmcore captured
- Check `/proc/<pid>/stack` for blocked thread call traces
